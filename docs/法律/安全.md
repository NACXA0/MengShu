# 安全策略 | Security Policy

> **不要通过公开 issue 报告安全漏洞。** 优先渠道见下文 §3。

---

## 0. 特别优先级：本项目的一票否决项

本项目的全部价值建立在一条架构红线上：**Vault 区数据向第三方的输出 = 0 字节**。因此，以下两类漏洞的优先级高于任何 CVSS 评分：

| 类别 | 定义 | 处理等级 |
|---|---|---|
| **R 类（红线突破）** | 任何把 Vault 明文、SM2 私钥或加密盐传出设备的路径——含调试日志、崩溃上报、埋点字段 | **Critical，无条件最高优先级** |
| **C 类（密码学失效）** | 裸哈希上链/入库（绕过 HMAC 加盐）、SM4 ECB 模式、自定义 SM2 曲线参数、非常量时间比较导致的时序侧信道 | **Critical** |

对照测试用例：**T-02（Vault/Plaza 隔离性渗透）**是本产品的一票否决项，任何形式的突破报告都会触发最紧急响应流程。

## 2. 范围（Scope）

### 2.1 In Scope

- 本仓库全部代码：客户端（iOS/Android/小程序）、协议层（双签/Merkle/墓碑规范）、AnchorBackend、Plaza 服务端；
- 国密算法调用封装与序列化规范（canonical JSON 哈希一致性）；
- Merkle 树构建与证明生成/验证逻辑；
- 安全芯片（Secure Enclave / StrongBox）交互层；
- 机构 API 网关的认证、授权、限流逻辑；
- 部署于 pactbook.org 域名下的官方公开页与核验服务；
- 依赖清单（THIRD_PARTY_NOTICES）所列组件的**集成方式**引入的漏洞（区分于组件自身 CVE，后者走依赖升级通道）。

### 2.2 Out of Scope

- 社会工程、钓鱼、物理攻击；
- 针对生产基础设施的纯拒绝服务（无数据完整性影响）；
- 无可复现证据的报告（仅理论攻击、未提供 PoC 或详细步骤）；
- 第三方组件自身的已知 CVE（请直接报告给对应上游项目；我们通过依赖升级与 SBOM 扫描响应）；
- 链上（至信链）的共识层问题（不在我们控制范围内）；
- 自建锚定节点（社区 AnchorBackend 实现）——请报告给对应维护者。
