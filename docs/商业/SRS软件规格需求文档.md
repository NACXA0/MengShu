| # | 假设/依赖 | 风险与兜底 |

## 3. 功能需求
### 3.1 Vault 模块（FV，零存储区）
#### FV-01 身份与账号【v2.0 全面重写】（←PRD FR-G1/G2/G3/G6）
**两级验证模型**：
| 级别 | 手段 | 证明 | API |
|---|---|---|---|
| L1 账户控制权 | `my.getAuthCode(scopes: 'auth_base')` 静默授权 → 服务端 `alipay.system.oauth.token` 换取 uid | 操作者控制该支付宝账户（已登录） | 支付宝开放平台 |
| L2 本人现场操作 | 支付宝**身份验证**产品（[开放平台说明](https://open.alipay.com/api/detail?code=I1080300001000044085&index=1)；**禁止**对外称为「人脸核验」产品） | 操作者确系该支付宝账户实名主体本人在场 | 支付宝开放平台身份验证 |
| # | 需求 | 规格 |
|---|---|---|
| FV-01.1【重写】 | 注册/登录 | L1 静默授权即可；服务端执行 `INSERT INTO user(alipay_uid) …`，UNIQUE 约束冲突 → 拒绝："该支付宝已绑定盟书账号" |
| FV-01.2 | 服务器身份字段 | **仅 `alipay_uid` 一个**（唯一索引）；无姓名、无证件号、无手机号、无人脸、无 person_token——**schema 级自证，开源后任何人可核验**（§6.2） |
| FV-01.3 | 密码体系 | 无自建密码；换设备登录 = 新设备上静默授权（uid 恒定），账号即恢复 |
| FV-01.4【重写】 | 本地盐 | 设备侧生成 32 字节随机 `user_salt`，存小程序加密缓存（`my.setStorage`），永不上传；**换设备须助记词恢复 Vault（盐随 Vault 备份包迁移，见 FV-02.2）** |
| FV-01.5 | DID 生成 | `DID = HMAC-SM3(user_salt, alipay_uid)`——注意 v2.0 起盐的输入为 uid（平台不接触证件号），上链与服务器均只见 DID |
| FV-01.6 | 唯一性校验 | `alipay_uid` 数据库 UNIQUE 约束（最终防线）；不提供换绑功能（一人终身一号，见 FV-11） |
| FV-01.7【新增】 | **敏感操作 certify 矩阵**（←PRD FR-G3） | 下表全部强制 L2 验证，未通过不得提交： |
| | | 双签确认（双方各自）、开启公示/调整名片可见性、提交关系陈述、场景 B 现场授权、注销账号 |
| | | 静默足够：授权码生成、浏览/核验（无需登录）、日常浏览 |
| FV-01.8【新增】 | certify 失败处理 | 用户中途退出（错误码 11）→ 敏感操作终止，不产生任何账单（失败不计费）；服务端不记录失败原因明细，仅计数（体验监控，NFR-C1） |
| FV-01.9【新增】 | 未成年人拦截 | 注册环节 18+ 自我声明 + TERMS 条款；强化路径（实名主体年龄标识接口）**待调研**（§9.2-V1）；冒用注册经核实 → 立即删除全部数据 |
#### FV-02 密钥管理【v2.0 修订】（适配小程序沙箱环境）
| # | 需求 | 规格 |
|---|---|---|
| FV-02.1【修订】 | 密钥生成 | SM2 密钥对在小程序 JS 环境生成（纯软件实现，emmansun/gmsm 或等价库【MIT/Apache-2.0】）；**已知降级**：无 Secure Enclave/StrongBox 硬件防护（论证见 FV-02.7） |
| FV-02.2【修订】 | 备份 | 助记词（256 位熵，BIP39 中文词库）经**用户口令派生密钥**（PBKDF2-SHA256，≥100,000 轮）SM4-GCM 加密后导出为备份包；`user_salt`、SM2 私钥、Vault 数据密钥全部包含于备份包内 |
| FV-02.3【修订】 | 迁移 | 新设备：静默授权登录（恢复账号，FV-01.3）+ 助记词 + 口令 → 本地解密备份包恢复 Vault；**迁移全程 Vault 明文不落任何中间服务器** |
| FV-02.4 | 销毁 | 销毁路径：小程序缓存清空（`my.clearStorage`）+ 助记词作废声明上链；销毁后本地明文与 salt 物理不可恢复 |
| FV-02.5【新增】 | 存储约束 | Vault 全部数据（加密后）存小程序缓存：**单 key ≤ 200KB，总计 ≤ 10MB**；Vault 数据结构须按此容量设计（预估：单条关系档案加密后 ≤ 2KB，支持数百段关系记录富余）；超限提示用户清理或等待 Phase 3 原生端迁移 |
| FV-02.6【新增】 | iOS 备份泄漏面 | 小程序缓存支持 iTunes 备份——备份为平台级加密数据，但**平台加密密钥非用户主控**；缓解：Vault 数据在平台加密之上再叠加 SM4-GCM 用户口令加密（双层），iTunes 备份获得的是密文，无口令不可解 |
| FV-02.7【新增】 | **密钥降级论证**（PRD 决策 D4 技术承接） | ① **威胁模型差异**：关系存证攻击收益为隐私损害，非资金盗取——与金融场景（必须硬件密钥）不同级；② **身份验证门控补偿**：密钥失窃者无法独立完成任何高价值操作（双签/公示/陈述/授权均须本人通过身份验证），攻击面收窄至"只读需先破口令加密"；③ **验证期成本约束**：Phase 1 目标为验证 H1/H2（北极星），原生 App（6-12 个月开发上架）与验证节奏冲突；④ **升级路径**：Phase 3+ 原生端提供 Secure Enclave/StrongBox 硬件密钥，助记词体系保证**无损迁移**（同一助记词派生，加密强度升级）；残余风险（设备+口令同时失窃→明文暴露）写入隐私政策已知限制节 |

#### FV-04 双签协议【v2.0 修订】（增加 certify 门控）
**状态机**【维持 v1.0，含图】：
```
INVITED ──拒绝(无痕)──→ VOIDED（邀请方界面恒显示"等待响应"）
   │接受
   ▼
DRAFTING（E2E 加密通道协商，服务器只见密文中继，SIGNED 后 24h 删除）
   │双方 certify + 点击确认【v2.0 新增门控】
   ▼
EXCHANGING_SIGS ── 双方 SM2 签名互换 ──→ SIGNED
   │ 提交锚定
   ▼
ANCHORED（返回存证编号 + Merkle proof）
```
| # | 需求 | 规格 |
|---|---|---|
| FV-04.1 | 协商通道 | 双方内容协商走 E2E 加密中继（SM4 会话密钥，双方 SM2 公钥协商），中继密文在 SIGNED 后 24h 内删除【维持】 |
| FV-04.2 | 哈希一致校验 | 双端各自计算 `digest = HMAC-SM3(shared_rel_salt, canonical_json(record))`，不一致拒绝进入签名【维持】 |
| FV-04.3 | 共享盐 | `shared_rel_salt` 发起方生成、E2E 通道传递，仅存双方设备【维持】 |
| FV-04.4 | 拒绝无痕 | 对方拒绝/放弃/超时，邀请方一律只见"等待对方响应"【维持】 |
| FV-04.5【修订】 | 签名对象与门控 | `sig_X = SM2_Sign(digest, sk_X)`；**进入 EXCHANGING_SIGS 前双方各自通过 certify**（法律签署行为必须本人在场）——签名与 certify 构成**双重证据**（PRD §2.4 信任主张） |
| FV-04.6 | 邀请码 | 一次性、24h 有效、可撤回生成【维持】 |
#### FV-05 锚定服务【v1.0 全节维持】
FV-05.1 插件接口 / 05.2 批量锚定（每小时 Merkle，单树 ≤10 万叶子）/ 05.3 证明留存 / 05.4 官方后端（至信链）/ 05.5 公开核验 / 05.6 降级策略——**内容不变，原文维持**。
#### FV-06 完整性宣誓【v1.0 维持 + v2.0 补】
FV-06.1 宣誓对象 / 06.2 证伪变更（双人复核+审计，唯一强制公开变更）/ 06.3 公示粒度——**内容维持**。certify 门控：宣誓提交须 L2 验证（归入 FV-01.7 矩阵的"开启公示"类）。
**【v2.0 补】跨账号证伪**：新账号对空历史宣誓"完整"而对方仍持有旧关系 Merkle proof/签名时，经法定渠道确认后触发 FV-06.2 强制公开变更。威慑是法律的——**平台不扫描旧锚定标记新号，不做跨账号技术关联**（PRD D6 层 3）。
