**版本**：v1.0 | **状态**：评审稿 | **密级**：内部
**编制依据**：GB/T 8567、ISO/IEC/IEEE 29148
**上游文档**：MRD v1.1（定稿）、PRD v1.0（冻结）
**追踪约定**：本 SRS 全部需求编号（FV/FP/FA/FB/NFR）将在 §8 RTM 中回链 PRD 的 FR 编号，测试用例编写时以本 SRS 编号为唯一锚点。

## 1. 引言
### 1.1 目的
本文档定义盟书（PactBook）软件系统的完整技术需求，供架构设计、开发、测试与法务合规作为实现与验收基准。凡与 PRD 冲突处，以“灵魂红线优先”原则裁决：Vault 区数据向第三方的输出 = 0 字节，此条不可被任何后续需求推翻。
### 1.2 范围
覆盖 Phase 1-2 全部范围（Vault、Plaza、场景 A/B API、分红入账、广告位），Phase 3 项（分红提现、机构免确认白名单）仅预留接口不实现。
### 1.3 定义与缩略语
| 缩略语 | 全称 | 说明 |
|---|---|---|
| DID | Decentralized Identifier | 本系统中为 `HMAC-SM3(user_salt, 证件号)` 的哈希值 |
| 锚定 | Anchoring | 将哈希摘要批量写入司法区块链的行为 |
| 墓碑 | Tombstone | 删除请求发生后上链的 `{digest, deleted_at}` 记录 |
| 有效期戳 | valid_until | 场景 A 响应自带的失效时间，用于约束撤回传播 |
| 双签 | Dual-Sign | 双方各自以 SM2 私钥对同一内容哈希签名 |
### 1.4 参考文档
MRD v1.1；PRD v1.0；GB/T 32905（SM3）、GB/T 32918（SM2）、GB/T 32907（SM4）；《个人信息保护法》（下称 PIPL）；《电子签名法》；至信链接入指南。

## 2. 总体描述
### 2.1 运行环境约束
| 项 | 约束 |
|---|---|
| 客户端 | iOS 15+ / Android 8+（须支持 StrongBox/Secure Enclave 的设备为完整功能档；不支持设备降级为软加密并显著提示） |
| 服务端 | 国内云部署，等保二级起步，Plaza 库与锚定服务物理分库 |
| 小程序 | 微信小程序轻版：仅公开页查看 + 授权码验证（不含 Vault 双签，因密钥安全不达标） |
| 密码套件 | SM2/SM3/SM4 + TLS 1.3 国密双证书（GM/T 0111） |
### 2.2 关键假设与依赖
| # | 假设/依赖 | 风险与兜底 |
|---|---|---|
| A-1 | 核身服务商可返回**同一自然人恒定的唯一标识**（person_token），用于服务器端防一人多号 | 若服务商不提供：以 certify_id 去重 + 合同约束 + 定期审计兜底，接受残余风险 |
| A-2 | 至信链按量计费可控（Merkle 批量锚定后单条成本厘级） | 捐赠不足时锚定降级为每日一次（见 FV-05.6） |
| A-3 | 陈述量级小（仅双签关闭关系的当事人可写），20% 人工抽审可行 | 举报率超阈值时自动提高抽审比例至 100% |
| A-4 | 公开页仅链接可达、无搜索，爬虫风险低 | 频控 + robots + 无列表页；异常抓取自动封禁 |

## 3. 功能需求
### 3.1 Vault 模块（FV，零存储区）
#### FV-01 身份与实名核身
| # | 需求 | 规格 |
|---|---|---|
| FV-01.1 | 核身外包 | 拉起微信/支付宝核身 SDK；平台仅接收并存储 `certify_id`、`certify_status`、`person_token`，**任何身份证号/姓名/人脸不得进入平台任何存储与日志** |
| FV-01.2 | 本地盐 | 设备安全芯片生成 32 字节随机 `user_salt`，永不上传、永不出安全芯片 |
| FV-01.3 | DID 生成 | `DID = HMAC-SM3(user_salt, 证件号)`，上链与服务器均只见 DID |
| FV-01.4 | 唯一性校验 | 服务器以 `person_token` 做账号去重（防 Sybil），见假设 A-1 |
| FV-01.5 | 年龄门槛 | 核身返回年龄 < 18 → 拒绝注册，不建立任何档案 |
| FV-01.6 | 核身凭证用途限定 | `person_token` 仅用于唯一性校验，禁止用于任何其他处理 |
#### FV-02 密钥管理
| # | 需求 | 规格 |
|---|---|---|
| FV-02.1 | 密钥生成 | SM2 密钥对在 Secure Enclave / StrongBox 内生成，私钥不可导出（白名单外） |
| FV-02.2 | 备份 | 助记词（256 位熵，BIP39 中文词库）经 SM4 加密后可导出纸质备份；助记词本身可派生加密备份包 |
| FV-02.3 | 迁移 | 新设备恢复 = 助记词 + 旧设备在线确认（双因子），迁移全程 Vault 明文不落任何中间服务器 |
| FV-02.4 | 销毁 | 销毁路径：设备密钥删除 + 助记词作废声明上链；销毁后本地明文与 salt 物理不可恢复 |
#### FV-03 关系档案（本地存储）
| # | 需求 | 规格 |
|---|---|---|
| FV-03.1 | 加密 | 本地库 SM4-GCM 加密，数据密钥由设备硬件密钥封装 |
| FV-03.2 | 记录结构 | `{rel_id, parties:[DID_A, DID_B], period:{start,end}, nature, closure_type, statements_local, version}` |
| FV-03.3 | 确定性序列化 | 上链前计算哈希使用规范化 JSON（键字典序、UTF-8、无空白），保证双端哈希一致 |
| FV-03.4 | 明文边界 | 明文仅在设备内存与本地加密库；任何导出（除助记词备份包）不允许 |
#### FV-04 双签协议
**状态机：**
```
INVITED ──拒绝(无痕)──→ VOIDED（邀请方界面恒显示"等待响应"）
   │接受
   ▼
DRAFTING（双方经端到端加密通道协商内容，服务器只见密文中继，
   中继报文完成后即删）──任一方放弃──→ ABANDONED
   │双方点击确认
   ▼
EXCHANGING_SIGS ── 双方 SM2 签名互换 ──→ SIGNED
   │ 提交锚定
   ▼
ANCHORED（返回存证编号 + Merkle proof）
```
| # | 需求 | 规格 |
|---|---|---|
| FV-04.1 | 协商通道 | 双方内容协商走 E2E 加密中继（SM4 会话密钥，双方 SM2 公钥协商），中继密文在 SIGNED 后 24h 内删除 |
| FV-04.2 | 哈希一致校验 | 双端各自计算 `digest = HMAC-SM3(shared_rel_salt, canonical_json(record))`，digest 不一致则拒绝进入签名步骤（防内容偷换） |
| FV-04.3 | 共享盐 | `shared_rel_salt` 由发起方生成、经 E2E 通道传递，仅存双方设备 |
| FV-04.4 | 拒绝无痕 | 对方拒绝/放弃/超时，邀请方一律只见“等待对方响应”，无已读、无超时提示 |
| FV-04.5 | 签名对象 | `sig_X = SM2_Sign(digest, sk_X)`，双方签名与 digest 一起构成存证单元 |
| FV-04.6 | 邀请码 | 一次性、24h 有效、可撤回生成 |
#### FV-05 锚定服务
| # | 需求 | 规格 |
|---|---|---|
| FV-05.1 | 插件接口 | `AnchorBackend` 为开源接口：`anchor(digests[]) → {merkle_root, tx_id, anchor_ts}`；社区可自建实现 |
| FV-05.2 | 批量锚定 | 每小时将期间全部 digest 构建 Merkle 树，仅树根上链至信链，单树上限 10 万叶子 |
| FV-05.3 | 证明留存 | 每条记录的 Merkle proof 由客户端本地留存；服务器留存树根索引供公开核验 |
| FV-05.4 | 官方后端 | 至信链（后续可扩展天平链直连），依据其接入指南完成企业主体注册 |
| FV-05.5 | 公开核验 | 任何人凭存证编号 + 明文摘要可在链上浏览器/核验接口验证 Merkle proof |
| FV-05.6 | 降级策略 | 捐赠余额低于阈值 → 锚定频率降为每日一次；产品内如实展示当前锚定周期 |
#### FV-06 完整性宣誓
| # | 需求 | 规格 |
|---|---|---|
| FV-06.1 | 宣誓对象 | 用户对 `{档案计数, 区间摘要, 宣誓日, "完整无遗漏"承诺}` 签名，签名结果作为一条记录走 FV-05 锚定 |
| FV-06.2 | 证伪变更 | 虚假宣誓经**法定渠道确认**后，状态强制变更为“曾有虚假宣誓记录”；变更须双人复核 + 证据链入审计日志（不可篡改），此为全产品唯一强制公开变更 |
| FV-06.3 | 公示粒度 | Plaza 仅公示宣誓状态（✅/⚠️/未宣誓），不公示宣誓内容 |
#### FV-07 授权码出示（本地验证）
| # | 需求 | 规格 |
|---|---|---|
| FV-07.1 | 生成 | 用户自选字段集 + 有效期（15min/1h/24h）→ 生成本地签名的出示包，二维码呈现 |
| FV-07.2 | 验证 | 验证方 App 扫码后**本地**验证签名，并向锚定服务拉取 Merkle proof 比对——全程验证方接触用户数据，服务器不经手内容 |
| FV-07.3 | 一次性 | 授权码使用一次后失效；失效后不向出示方回显“是否曾被使用”之外的任何信息 |
| FV-07.4 | 隐写水印 | 二维码含验证时间与验证对象哈希的隐写水印，用于滥用溯源 |
#### FV-08 关系关闭
| # | 需求 | 规格 |
|---|---|---|
| FV-08.1 | 和平关闭 | 双签关闭协议，关闭记录（含关闭方式、双方可选结语）走 FV-05 锚定 |
| FV-08.2 | 单方注销 | 一方发起即标记，30 天内对方可附说明；逾期维持单方标记。单方关闭满 30 天后双方获得陈述资格（见 FP-03） |
#### FV-09 删除（墓碑机制）
| # | 需求 | 规格 |
|---|---|---|
| FV-09.1 | 本地删除 | SM4 数据密钥 + 全部 salt 销毁 → 明文物理不可恢复 |
| FV-09.2 | 墓碑上链 | `{digest, deleted_at}` 上链声明；明文与盐俱灭后，链上残留哈希失去字典攻击面，依 PIPL 第 4 条匿名化认定完成删除义务 |
| FV-09.3 | Plaza 删除 | 公示撤下后服务器数据保留 ≤ 30 天后物理删除 |
#### FV-10 设备迁移
| # | 需求 | 规格 |
|---|---|---|
| FV-10.1 | 流程 | 助记词恢复 + 旧设备确认；Vault 数据重新以新设备密钥加密 |
| FV-10.2 | 无云备份 | 不提供任何服务器备份路径（服务器无可备份数据），此约束写入用户文档 |

### 3.2 Plaza 模块（FP，服务器存储区）
#### FP-01 公示管理（←FR-A1）
| # | 需求 | 规格 |
|---|---|---|
| FP-01.1 | 默认关闭 | 全字段默认 OFF；开启需二次确认弹窗（“将对所有持链接陌生人可见”） |

| FP-01.5 | 变更频控 | 字段调整每日限 1 次 |
| FP-01.6 | 版本化 | 公示配置带版本号，全部变更入审计日志 |
#### FP-02 公开主页（←FR-A2）
| # | 需求 | 规格 |
|---|---|---|
| FP-02.1 | 链接唯一可达 | 无站内搜索、无列表页、无推荐；仅用户分享的链接/二维码可达 |
| FP-02.2 | 频控 | 单 IP 单主页 ≤ 10 req/min；超限 429 |
| FP-02.3 | 反爬 | robots 全禁、无 sitemap、无结构化列表 API |

| FP-02.5 | 性能 | P95 < 500ms |
#### FP-03 关系陈述（←FR-B1~B5）
**陈述生命周期状态机：**
```
（关系关闭且双方核身）→ 可写
DRAFT → L1(PII正则) → L2(敏感词) → [抽审] → VISIBLE
VISIBLE → 7天可改 → LOCKED
举报 → UNDER_REVIEW →（≤24h）REMOVED | RESTORED
公示撤下 → HIDDEN →（30天）→ DELETED
```
| # | 需求 | 规格 |
|---|---|---|
| FP-03.1 | 资格引擎 | 关系状态 ∈ {和平关闭， 单方关闭满30天} 且双方均已核身，方可提交；每关系每人限 1 份 |
| FP-03.2 | L1 过滤 | PII 正则（手机号/身份证号/微信号/常见姓名格式）拦截率须为 100%，含变体（空格、分隔符混淆）测试集 |
| FP-03.3 | L2 过滤 | 敏感词库初筛 + ≥ 20% 抽样人工复审；举报率超阈值自动升至 100% 人工 |
| FP-03.4 | 双向并列 | 陈述与其答辩（如有）同一渲染单元、同权重展示；**不存在任何单方删除对方文本的技术路径**；未提交方显示中性占位文案 |
| FP-03.5 | 法律告知门 | 提交前强制阅读并勾选法律告知（诽谤责任 + 追责链条说明），未确认不可提交 |
| FP-03.6 | 存储 | Plaza 独立库，AES-256 加密，库密钥 HSM 管理；与 Vault 物理隔离（渗透测试必测项） |
| FP-03.7 | 通知删除 | 举报 → 人工审 → 处理 ≤ 24h；处理结果与理由入审计日志 |
| FP-03.8 | 长度 | ≤ 200 字，纯文本，禁图禁链 |

### 3.3 机构 API 模块（FA）
#### FA-01 机构准入（←FR-C3）
| # | 需求 | 规格 |
|---|---|---|
| FA-01.1 | 双向认证 | mTLS（机构客户端证书）+ IP 白名单 + API Key 三重 |
| FA-01.2 | 合同门 | 未签数据合规承诺书（用途限定/禁止缓存转售/违约金/审计权）不得开通 |
| FA-01.3 | 配额 | 单机构 QPS ≤ 1（令牌桶）；预充值套餐余额管控 |
#### FA-02 场景 A：批量查询公示信息（←FR-C1）
```
POST /v1/public/query
Headers: mTLS + X-Api-Key + X-Signature(请求体SM2/HMAC签名)
Body:   { "subject_public_id": "pb_xxxx",
          "fields": ["relationship_band","attestation_status","statements"] }
200 响应:
{ "granted_fields": {...},          // 仅请求且已公示的字段
  "attestation_hash": "0x…",        // 供机构自行核验
  "verify_url": "https://…",        // 链上核验入口
  "valid_until": "2026-10-21T10:35:00Z" }   // 有效期戳 ≤ 5min
404 用户不存在或未公示 / 403 字段未公示 / 429 超限
```
| # | 需求 | 规格 |
|---|---|---|
| FA-02.1 | 数据边界 | **仅 Plaza 已公示字段**；字段级白名单在网关二次强制（纵深防御） |
| FA-02.2 | 法律依据落地 | PIPL 第 27 条：仅处理自行公开信息；撤回（“明确拒绝”）后不得再处理 |
| FA-02.3 | 有效期戳设计 | 每个响应携带 `valid_until = now + 5min`；合同强制机构在 valid_until 后不得继续使用该数据——**撤回传播由 TTL 天然兜底**，即使缓存失效机制故障 |
| FA-02.4 | 计费 | 返回 200 且含数据才计费；拒绝/无公示不计费 |
| FA-02.5 | 审计 | 全量查询日志 ≥ 3 年，同步至被查用户台账（FP-04.2）并触发分红（FP-05.1） |
#### FA-03 场景 B：本人现场授权（←FR-C2）
```
① POST /v1/consent/init      机构发起 → 返回授权页URL（10min内有效）
② 用户在授权页看到六要素：机构名/联系方式/目的/字段/保存期限/权利告知
   逐项勾选字段 → 确认（PIPL第23条单独同意，全屏独立页，不与其他勾选混同）
③ GET  /v1/consent/callback  → 返回 authorization_code（5min，单次）
④ POST /v1/consent/exchange   → code 换 access_token（10min，单次拉取）
⑤ POST /v1/consent/data      → 凭令牌拉取授权字段（摘要级）
⑥ 传输凭证写入用户授权台账（FP-04.1）
```
| # | 需求 | 规格 |
|---|---|---|
| FA-03.1 | 单独同意 | 授权页为全屏独立界面，六要素逐项展示，字段逐个勾选；不得与任何其他授权合并 |
| FA-03.2 | 摘要边界 | 可授权字段集 = Plaza 公示字段 + 存证核验 URL；**Vault 明细不在此集合中——即本人现场授权也不可突破** |
| FA-03.3 | 令牌约束 | code 5min/单次；access_token 10min/单次拉取；拉取后即焚 |
| FA-03.4 | 拒绝语义 | 拒绝/超时（10min 上限）统一返回机构侧“用户未授权”，不含原因 |
| FA-03.5 | 删除协助 | 用户行使删除权时，平台向已接收数据的机构转发删除协助通知，通知本身入审计日志 |
| FA-03.6 | 费用 | 传输免费；仅收机构系统对接开通费 |

## 6. 数据需求
### 6.1 分类分级（承接 MRD，细化存储位置）
| 级 | 数据 | 位置 | 保留 |
|---|---|---|---|
| L4 | Vault 明文、私钥、各盐 | 仅设备（安全芯片/本地加密库） | 用户主控，销毁即灭 |
| L3 | certify_id / person_token | 服务器（加密） | 账号存续期 |
| L2 | Plaza 公示字段、陈述、答辩 | Plaza 库（AES-256） | 撤下后 ≤ 30 天删除 |
| L1 | 哈希、签名、Merkle proof 索引、审计日志 | 服务器/链 | ≥ 3 年（法定与司法需要） |
### 6.2 服务端数据结构（Plaza，示意）
```sql
plaza_profile(user_public_id PK, field_flags JSONB, band_setting,
              status, version, published_at, updated_at)
plaza_statement(statement_id PK, relationship_id, author_did_hash,
               content_enc BYTEA, status ENUM, locked_at)
plaza_rebuttal(statement_id FK, content_enc, submitted_at)
consent_record(consent_id PK, org_id, user_public_id, fields[],
              purpose, granted_at, expires_at, status)
org_client(org_id PK, mtls_cert, ips[], api_key_hash,
           quota, balance, contract_flags)
api_query_log(query_id PK, org_id, subject_public_id, fields[],
              billed BOOL, valid_until, ts)
dividend_ledger(entry_id PK, user_public_id, query_id FK, amount, status, ts)
audit_log(event_id PK, event_type, actor, subject, detail_hash, ts)  -- append-only
```
**注意**：无任何表包含姓名/手机号/身份证/人脸字段——这是 schema 级自证，开源后任何人都可核验。
