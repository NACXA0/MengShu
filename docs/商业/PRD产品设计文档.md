## 2. 产品概述
### 2.1 一句话定位
双边签认、密码学存证、开源免费的关系信任基础设施：Vault 区保存用户自持的秘密，Plaza 区承载用户自愿挂出的招牌，两者物理隔离、数据永不相通。
### 2.1.1 产品物种【v2.0 补】
功能实质是**双边签署 + 存证 + 核验**。盟书与 e签宝、法大大属于同一物种，签署标的物是关系而非合同。不提供任何撮合、浏览、发现、匹配——e签宝不会因有人用它签婚前协议就变成婚恋平台，公证处不会因有人来公证结婚材料就变成婚姻介绍所。
**真实风险（须诚实面对）**：审核员按使用场景而非功能实质归类的概率不低。最“婚恋化”的表面是公开主页（把关系史展示给陌生人看）。缓解与解锁路径见合规清单第 12 项与 §14-D5；基线端矩阵不变（公开主页已由 H5 承载），路径②仅为类目驳回后的预案。
### 2.2 产品目标（Phase 1-2）
| 目标 | 衡量 |
|---|---|
| 验证核心假设 H1：认真关系愿意互证 | 月互证次数 ≥ 5000 |
| 验证核心假设 H2：经历清白者愿意公示 | 公示率 ≥ 15% |
| 验证核心假设 H3：机构愿意为授权查询付费 | 种子机构 ≥ 1 家完成付费闭环 |
| 守住灵魂红线 | Vault 区数据向第三方的输出 = 0 字节 |
| **【v2.0 新增】身份层健康度** | 认证放弃率 ≤ 10%（体验红线）；一人一号违规检出为 0 |
### 2.3 范围外（明确不做）
- 任何形式的匹配、推荐、排行、评分、诚信分；
- **【v2.0 明确】评星、星级、结构化标签式评价及其一切排序化变体**（经完整评估后否决，决策记录见 §14-D1）；
- 任何形式的定向广告或用户画像；
- 任何金钱兑付型承诺（吸取“恋爱合约”“爱情银行”崩盘教训）；
- Vault 区明细向任何第三方（含用户现场授权的机构）的输出——**任何商业模式不在此开缝**；
- 搜索入口：公开页只能通过链接到达，不可被搜索到；
- **【v2.0 新增】双身份生态并行**：不接入微信身份体系（微信小程序不做）；微信内核身通道仅作灾备预案，不面向用户开放（决策见 §14-D3）。
### 2.4 核心卖点（唯一）
**可信**：所有输出到 Plaza 的信息都带司法级存证凭证，可被任何机构或个人独立核验真伪，而平台本身不掌握任何原始数据。
**【v2.0 强化】信任主张升级为双重证据**：
| 证据层 | 证明什么 | 由谁背书 |
|---|---|---|
| 密码学层 | 内容未被篡改、签署不可抵赖 | 国密算法 + 至信链司法锚定 |
| 身份层 | 操作者确系本人、一人一号 | 支付宝实名体系 + certify 人脸核验 |
### 2.5 双层信任架构【v2.0 新增】
```
┌─────────────────────────────────────┐
│ 身份层（支付宝生态）                   │
│ 静默授权 → uid → 注册/登录/防多号      │
│ certify  → 人脸 → 敏感操作本人确认     │
│ 平台只见：uid + passed 布尔值          │
├─────────────────────────────────────┤
│ 密码学层（自持）                       │
│ SM4 端侧加密 → Vault 零存储           │
│ HMAC-SM3 加盐哈希 + SM2 双签          │
│ Merkle 批量锚定 → 至信链               │
└─────────────────────────────────────┘
```
两层的分工与互补：身份层解决“你是谁”（原方案依赖假设 A-1 的架构缺口，现已闭合）；密码学层解决“内容可信”。**certify 门控同时补偿了小程序端密钥安全的降级**——密钥失窃者无法独立完成任何高价值操作（见 §14-D4 论证）。

## 3. 用户角色与权限矩阵
| 角色 | Vault 区 | Plaza 区 | 关系陈述 | 机构 API | 数据分红 |
|---|---|---|---|---|---|
| 注册用户（本人） | 完整读写 | 完整读写+公示开关 | 提交/答辩 | 授权/拒绝 | 提现/抵扣 |
| 关系对方（前任） | 关系记录共签 | 本人陈述的并列展示 | 提交/答辩 | — | — |
| 未注册陌生人 | 不可见 | 仅公示字段可见 | 仅公示陈述可见 | — | — |
| 机构（白名单） | **永不可见** | 仅 API 白名单字段 | 仅公示陈述 | 查询+计费 | — |
| 平台运营 | **无权读取**（架构性规避） | 审核后台（定向审核） | 审核后台 | 计费审计 | 结算 |
**关键设计原则**：平台对 Vault 区的“不可见”不是权限配置，而是架构性事实——Vault 明文只存在于用户设备 SM4 加密沙箱，服务器只有加盐哈希。**【v2.0 明确】服务器身份字段仅 `alipay_uid` 一个（唯一索引），无姓名、无证件号、无手机号、无人脸。**

## 5. 功能需求详述
### 5.1 模块 A：公示管理（Plaza 核心）
**FR-A1 公示开关**
| 项 | 规格 |
|---|---|
| 默认状态 | **全部字段默认不公示**，用户须显式 opt-in |
| 可选字段 | ① 存证关系数（区间显示，如"3-5 段”，防精确数字歧视）② 关闭方式分布 ③ 完整性宣誓状态 ④ 关系陈述精选 ⑤ 存证徽章 |
| **【v2.0 补】强制字段** | **注册时长**：公开页一旦发布（任一可选字段开启），注册时长**强制展示且不可单独关闭**；整页撤下后才消失。中性事实、无评判——新账号就是新账号的样子（“干净档案 + 注册 2 个月”本身可读）。期满重注的 `created_at` 重新起算 |
| 禁止字段 | 具体日期、前任任何信息、未公示关系的存在本身、精确数字 |
| 撤回 | 一键撤下，公开页 ≤ 1 分钟下线，API ≤ 5 分钟失效（依《个保法》第 15 条） |
| 修改频率 | 字段调整每日限 1 次（防反复横跳操纵） |
| 二次确认 | 公示前强制展示“此内容将对所有持有链接的陌生人可见”弹窗 |
| **【v2.0 新增】本人核验** | 开启公示须先通过支付宝 certify 人脸核验（单独同意的法律要件 + 本人操作证明） |
**FR-A2 公开主页**
- 仅含公示字段摘要、存证徽章（可点击核验）、分红说明、举报入口；
- **无任何搜索入口**——只能通过用户主动分享的链接/二维码到达；
- 防爬：频次限制、无列表页、robots 屏蔽；
- **【v2.0 明确】H5 承载公开主页，须在微信内置浏览器内正常渲染与核验**（验收见 US-08）；
- 视觉规范：克制、无打分元素、无任何价值排序。
**FR-A3 完整性宣誓状态公示**
- 用户可公示“完整性宣誓状态”（✅ 已宣誓 / 未宣誓）而非宣誓内容本身；
- 一旦宣誓被证伪（法定渠道确认虚假宣誓），状态强制变更为“⚠️ 曾有虚假宣誓记录”，此变更公开且不可关闭（本产品唯一的强制公开变更）；
- **【v2.0 新增】与名片联动**：当名片可见范围小于“全部历史”时，宣誓状态旁须标注“档案完整，公开范围受限”（防“选择性公开”被误读为“就这么多”）。
- **【v2.0 补】跨账号证伪（注销洗白层 3）**：新账号对空历史宣誓“完整”，而旧关系的锚定证据仍在对方手里，构成虚假宣誓。击破依赖对方持有的 Merkle proof 与签名，配合传统证据链（聊天记录、共同照片、证人），经法定渠道确认后触发强制公开变更。威慑是法律的，不是技术的——**平台不扫描旧锚定去标记新号，不做跨账号技术关联**。
**FR-A4 个人名片与历史可见粒度【v2.0 新增，Phase 2】**
| 项 | 规格 |
|---|---|
| 定位 | 公开主页的丰富化扩展——身份层由支付宝实名背书后，公示字段可信度不再依赖平台自证，可安全放开展示粒度 |
| 可见性三态 | **全部历史 / 近期一段 / 全不公开**（默认全不公开） |
| “近期”语义 | **事件切片**（最近一段关系至今），非时间切片（“近一年”）——事件才是婚恋场景有意义的信息单元 |
| 自我陈述区 | 可选，≤ 100 字，复用模块 B 的 PII 过滤链（L1 正则 + L2 敏感词 + L3 举报） |
| 变更核验 | certify（本人操作） |
| 修改频率 | 每日 1 次（与 FR-A1 一致） |
### 5.2 模块 B：关系陈述（二人实名证言）
**定位**：附加功能，非核心。为公示档案增加“来自前关系方的证言”。**【v2.0 明确】本模块是本产品唯一的“评价类”功能，评星/评分体系已评估并否决（§14-D1）。**
**FR-B1 提交资格**
| 项 | 规格 |
|---|---|
| 资格 | 双方**均已实名核身** + 该关系**已双签关闭**（和平关闭或单方注销满 30 天） |
| **【v2.0 新增】本人核验** | 提交前须通过 certify（实名追责链条的前提） |
| 唯一性 | 每段关系每人仅 1 份陈述，提交后 7 天内可修改，之后锁定 |
| 长度 | ≤ 200 字 |
**FR-B2 内容合规（三层过滤）**
| 层 | 机制 |
|---|---|
| L1 自动 | PII 正则拦截（姓名/手机号/身份证/微信号 100% 拦截） |
| L2 敏感词 | 敏感词库初筛 + 抽样人工复审 ≥ 20% |
| L3 举报 | 举报通道 + 通知删除响应 ≤ 24h（《民法典》1195-1197 条义务） |
**FR-B3 双向并列展示（法律核心）**
- A 的陈述与 B 的答辩**永远并列展示**，不可单方删除对方文本；
- 未提交方显示“对方已提交陈述，你未提交”（中性文案，无催促暗示）；
- 双方均未提交显示“双方均未提交陈述”（完全中性）。
**FR-B4 法律告知（提交前强制）**
> “陈述一旦提交将与其公开档案关联，构成个人信息处理；涉诽谤责任由发布者承担。你的实名信息与关系存证已绑定，追责链条完整。”
**FR-B5 存储**
- 明文存 Plaza 区服务器，与 Vault 区物理隔离的独立数据库；
- 公示撤下时，陈述同步从公开页消失，服务器保留 ≤ 30 天后删除。
### 5.3 模块 C：机构 API（营收核心）
**FR-C1 场景 A：批量查询公示信息**
| 项 | 规格 |
|---|---|
| 数据范围 | **仅 Plaza 已公示字段**，不含 Vault 任何数据 |
| 法律依据 | 《个保法》第 27 条 |
| 撤回效力 | 用户撤下公示后，API 即时失效；响应携带 `valid_until`（≤5 分钟），合同强制机构过期不得使用 |
| 计费 | 按次计费，套餐预充值；单机构 QPS ≤ 1 |
| 分红 | 被查用户获查询费 30% 分成（详见 FR-E1） |
| **【v2.0 新增】成本内含** | 查询定价内含认证成本摊销（“谁消费信任，谁支付信任的成本”——路径 C，见 §8.4） |
**FR-C2 场景 B：本人现场授权传输**
法律依据：《个保法》第 23 条。OAuth 2.0 授权码流程：
```
① 用户在机构门店/机构 App 内点击"授权盟书档案"
② 跳转盟书授权页（六要素：机构名/联系方式/目的/字段/保存期限/权利告知）
③ 用户逐项勾选授权字段 → 【v2.0】通过 certify 本人核验
④ 盟书生成授权码返回机构
⑤ 机构凭授权码换取 access_token（≤10 分钟，单次拉取）
⑥ 机构凭令牌拉取授权字段（传摘要不传明细）
⑦ 传输凭证写入用户"授权记录"（可查、可撤销协助转发）
```
| 项 | 规格 |
|---|---|
| 令牌时效 | ≤ 10 分钟，单次拉取 |
| 传输内容 | **传摘要不传明细**——Vault 明细永不出境 |
| 审计 | 全部授权/查询日志保留 ≥ 3 年，用户可查 |
| 删除协助 | 用户行使删除权时，平台协助通知机构 |
| 费用 | 场景 B 传输免费（降低机构接入门槛）；**【v2.0】用户的 certify 成本由平台承担（路径 A，见 §8.4）** |
**FR-C3 机构准入**
- 企业资质审核 + 行业备案 + 数据合规承诺书 + 白名单制；

### 5.7 模块 G：身份与账号（支付宝生态绑定）【v2.0 新增】
**FR-G1 注册与登录（静默授权）**
| 项 | 规格 |
|---|---|
| 注册 | 支付宝小程序内 `getAuthCode` 静默授权，获取 uid（open_id） |
| 服务器存储 | `user(user_id PK, alipay_uid UNIQUE, ...)`——**身份相关字段仅此一个** |
| 密码体系 | 无（无自建密码、无手机号注册路径） |
| 覆盖前提 | 用户须持有已完成实名的支付宝主账户（写入 TERMS 注册资格） |
**FR-G2 防多号（一人终身一号）**
| 项 | 规格 |
|---|---|
| 最终防线 | `alipay_uid` 数据库 UNIQUE 约束；重复注册直接拒绝：“该支付宝已绑定盟书账号” |
| 换绑 | **不提供**——换支付宝账户=换人，须走注销→冷却→重注全流程 |
| 有效性来源 | 支付宝 KYC 层（一证件号一主账户），金融级攻击成本 |
**FR-G3 敏感操作本人核验矩阵（certify）**
| 节点 | 验证方式 | 理由 |
|---|---|---|
| 注册/登录 | 静默授权 | 拿 uid 即可，无感 |
| **双签确认** | **certify（双方各自）** | 法律签署行为，必须本人在场 |
| **开启公示/调整名片可见性** | **certify** | 单独同意的法律要件 |
| **提交关系陈述** | **certify** | 实名追责的前提 |
| **场景 B 现场授权** | **certify** | 向第三方提供个人信息（第 23 条），与公示同级敏感 |
| 授权码生成 | 静默 | 出示自己的数据，风险自担 |
| 浏览公开页/核验 | 无需登录 | 公开数据不设门槛 |
| 注销账号 | **certify** | 不可逆操作的最终确认 |
产品原则：**刷脸即法律动作**——每次 certify 对应一次单独同意或签署，界面措辞严肃（“确认提交陈述”而非“晒一下”）。这些操作本身均为人生低频事件（关系的开始、结束、公示决定），年触发次数个位数。
**FR-G4 注销与防洗白四层机制【v2.0 补扩展】**
冷却只是第 1 层。平台**不把新旧账号在技术上串起来**（新账号 = 新 uid 绑定关系下的新盐、新 DID；冷却记录期满物理删除，无法从哈希反推旧 uid）。
```
注销时：
  删除本账号 Plaza 数据，以及本账号作为作者的陈述（墓碑机制照常）
  ——碰不到对方设备上的档案、对方持有的证明、链上已锚定哈希、对方作为作者的陈述
  写入 cooldown 表：HMAC-SM3(platform_key, alipay_uid) + 注销时间戳
冷却期内（90 天）：
  同一支付宝再注册 → 拒绝："该支付宝在注销冷静期内"
期满：
  cooldown 记录物理删除，可重新注册（全新账号，无历史数据）
```
| 层 | 机制 | 性质 |
|---|---|---|
| **1** | **90 天冷却**——注销后短期无法重注；HMAC-SM3 加平台盐，不可反推 uid、不可跨平台关联 | 滥用防范（合法利益，《个保法》第 19 条允许的最短必要保留） |
| **2** | **注册时长强制展示**——公开页一旦发布即展示，不可单独关闭（见 FR-A1）；新账号 `created_at` 重新起算 | 中性事实，无评判——“干净档案 + 注册 2 个月”本身可读 |
| **3** | **完整性宣誓可证伪**——新账号对空历史宣誓“完整”而旧锚定关系存在 = 虚假宣誓；对方持有 Merkle proof/签名 + 传统证据链击破 → 强制公开“曾有虚假宣誓记录”（FR-A3 / FV-06.2） | 威慑是法律的，不是技术的；平台不做跨账号扫描关联 |
| **4** | **对方记录独立存续**——前任关于那段关系的锚定证据是前任的数据，删除权碰不到；对方的陈述是对方的内容，注销不触碰（对对方陈述的权利走通知-删除通道） | 数据主权边界的正确划分 |
冷却期内：不创建任何新档案、不恢复旧数据。期满重注为全新账号（新盐、新 DID、新 `created_at`），无历史 Plaza 数据。
**FR-G5 生态灾备（fail-closed）**
| 场景 | 行为 |
|---|---|
| certify / 授权服务不可用 | 敏感操作暂停，显示“身份核验服务暂不可用，请稍后重试”；**不做降级放行** |
| 支付宝小程序整体不可用 | H5 公开页与核验不受影响；本地待锚定队列照常 |
| 长期依赖风险 | 灾备预案：微信核身通道技术预研保持热备，**仅灾备启用，不做用户可选**（双通道并存=双 uid 体系=防多号复杂度翻倍） |
**FR-G6 未成年人拦截**
| 项 | 规格 |
|---|---|
| 要求 | 未满 18 周岁不得注册（不变） |
| 机制 | 注册环节自我声明 18+ + 条款约束；强化路径（支付宝实名主体年龄标识接口）**待 SRS 调研接口能力** |
| 残余风险 | 未成年人冒用成年人账户/家庭共用账户场景无法 100% 拦截，写入假设 A-2；一经核实立即删除全部数据 |
| 边界说明 | 家庭共用支付宝账户的账号归属，以支付宝实名主体为准（架构性接受，见 US-F12） |

### 6.1 主路径
| ID | 用户故事 | 验收标准 |
|---|---|---|
| US-01 | 作为认真恋爱者，我想与对方进行双签互证，以便这段关系被郑重记录且不可抵赖 | 双方各自通过 certify 后完成 SM2 签名；链上可查；任一方事后篡改本地记录，重算哈希与链上不匹配，篡改立即暴露 |
| US-02 | 作为经历清白者，我想把档案摘要挂到 Plaza 公示，以便让“可信”成为择偶竞争力 | certify 通过后可开启；公示后生成公开链接（H5），陌生人打开可见所选字段，区间化显示 |
| US-03 | 作为求证者，我想验证对方出示的公示档案真实性 | H5 公开页存证徽章可点击核验，链上哈希比对通过显示 ✅（**须在微信内置浏览器内可用**） |
| US-04 | 作为公示用户，我想随时一键撤下公示 | 撤下后公开页 ≤ 1 分钟下线，API ≤ 5 分钟失效 |
| US-05 | 作为机构，我想批量查询用户公示信息 | 仅返回 Plaza 白名单字段，无 Vault 数据路径可达；撤回用户数据实时失效 |
| US-06 | 作为到店客户，我想现场授权机构获取我的档案摘要 | OAuth2.0 流程 + 六要素弹窗 + certify 本人核验，传摘要不传明细 |
| US-07 | 作为被查用户，我想知道谁查了我并因此获得收益 | 每次查询实时通知，分红 T+1 入账（支付宝账户），明细一一对应 |
| **US-08【v2.0 新增】** | 作为在微信里收到分享链接的查看者，我想直接打开查看 | H5 公开页在微信内置浏览器正常渲染，核验功能完整，不要求跳转支付宝 |

**双层架构**：
| 层 | 机制 |

### 13.1 术语表
| 术语 | 含义 |
|---|---|
| Vault 区 | 用户自持的关系档案区，明文仅存设备，服务器零存储 |
| Plaza 区 | 用户自愿公示的公开区，存服务器，可随时撤下 |
| 双签 | 双方各自用 SM2 私钥对同一哈希签名；v2.0 起附 certify 本人核验，构成双重证据 |
| **uid（open_id）** | 支付宝分配的匿名用户标识，盟书服务器唯一的身份字段 |
| **静默授权** | `getAuthCode` 无感获取 uid，证明账户控制权 |
| **certify** | 支付宝人脸核验，证明本人现场操作 |
| **注销冷却** | 注销后 HMAC 化 uid 保留 90 天，期满物理删除（防洗白四层之层 1，见 FR-G4） |
| **注册时长（强制）** | 公开页发布后强制展示、不可单独关闭；中性事实，防“干净档案”隐瞒新号身份 |
| 完整性宣誓 | 用户对"本档案即全部”的数字签名，可被日后证伪 |
| 场景 A | 机构批量查询 Plaza 公开信息（付费 API） |
| 场景 B | 本人现场授权 → OAuth2.0 + certify → API 传输至机构（免费） |
| 数据分红 | 被查用户获查询费 30% 分成 |
| 墓碑交易 | 删除后上链的 {digest, deleted_at} 记录 |

场景 A：POST /v1/public/query

## 14. 决策记录【v2.0 新增】
| # | 决策 | 结论 | 核心依据 |
|---|---|---|---|
| D1 | 关系评价/评星功能 | **否决** | ① 评分语义与“事实存证”定位冲突，产品叙事滑向“给前任打分”（舆论毒药）；② 系统出分即成为评价背书方，名誉权连带风险升级；③ 看准网前车之鉴（商业模式被“付费消差评”动机结构反向劫持）。模块 B（实名+存证+双向并列的陈述）已覆盖正当需求，红线维持 |
| D2 | 身份层方案 | 支付宝生态绑定，替代原“自建核身+假设 A-1" | 原方案“一人多号”防御依赖核身方恒定标识的残余风险，是架构缺口；支付宝 KYC 的 uid 唯一性为金融级；平台仅取 uid + passed 两字段，与零存储红线完全兼容（外包核身，不外包信任链核心） |
| D3 | 平台策略 | 支付宝小程序主端 + H5 公开层 + PC（B 端，Phase 2）；不做微信小程序与原生 App（Phase 3+ 前） | 身份链路在支付宝端最完整；公开页须生态外可达（H5 覆盖微信内场景）；验证期成本约束下原生 App（6-12 个月开发上架）与验证节奏冲突；微信身份体系并存 = 双 uid = 防多号复杂度翻倍 |
| D4 | 小程序内完成双签（修订原 SRS §2.1"小程序不支持双签”） | **修订执行**，附论证与升级路径 | ① 威胁模型：关系存证攻击收益为隐私损害，非资金盗取，口令派生加密在此模型下可接受；② 补偿：certify 门控覆盖全部敏感操作，密钥失窃者无法独立完成高价值动作；③ H1 验证（北极星）要求双签在 Phase 1 大规模可用；④ 助记词体系保留向 Phase 3+ 原生 App 安全芯片的无损迁移路径。残余风险（设备+口令同时失窃→明文暴露）写入已知限制与隐私政策告知 |
| **D5【补】** | 小程序类目主张与 V3 解锁 | **按序三路径，V3 保持 Phase 1 阻塞** | 功能实质为签署存证工具（§2.1.1）；审核员按场景归类风险真实存在。① 预咨询主张工具类 → ② 驳回则 H5 分拆（公开主页不进小程序容器）→ ③ 最后才走婚恋证照。路径②启用前**不改**基线端矩阵 |
| **D6【补】** | 注销洗白防御 | **四层机制，平台不做跨账号技术关联** | ① 90 天冷却（PIPL 19）；② 公开页注册时长强制展示（中性事实）；③ 完整性宣誓可证伪（法律威慑，对方持有 proof）；④ 对方数据与陈述独立存续。新账号 = 新 uid/盐/DID；冷却期满物理删除，不可反推旧身份 |
