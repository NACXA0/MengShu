## 2. 产品概述
### 2.1 一句话定位
双边签认、密码学存证、开源免费的关系信任基础设施：Vault 区保存用户自持的秘密，Plaza 区承载用户自愿挂出的招牌，两者物理隔离、数据永不相通。
### 2.2 产品目标（Phase 1-2）
| 目标 | 衡量 |
|---|---|
| 验证核心假设 H1：认真关系愿意互证 | 月互证次数 ≥ 5000 |
| 验证核心假设 H2：经历清白者愿意公示 | 公示率 ≥ 15% |
| 验证核心假设 H3：机构愿意为授权查询付费 | 种子机构 ≥ 1 家完成付费闭环 |
| 守住灵魂红线 | Vault 区数据向第三方的输出 = 0 字节 |
### 2.3 范围外（明确不做）
- 任何形式的匹配、推荐、排行、评分、诚信分
- 任何形式的定向广告或用户画像
- 任何金钱兑付型承诺（吸取"恋爱合约""爱情银行"崩盘教训）
- Vault 区明细向任何第三方（含用户现场授权的机构）的输出——**任何商业模式不在此开缝**
- 搜索入口：公开页只能通过链接到达，不可被搜索到
### 2.4 核心卖点（唯一）
**可信**：所有输出到 Plaza 的信息都带司法级存证凭证，可被任何机构或个人独立核验真伪，而平台本身不掌握任何原始数据。

## 3. 用户角色与权限矩阵
| 角色 | Vault 区 | Plaza 区 | 关系陈述 | 机构 API | 数据分红 |
|---|---|---|---|---|---|
| 注册用户（本人） | 完整读写 | 完整读写+公示开关 | 提交/答辩 | 授权/拒绝 | 提现/抵扣 |
| 关系对方（前任） | 关系记录共签 | 本人陈述的并列展示 | 提交/答辩 | — | — |
| 未注册陌生人 | 不可见 | 仅公示字段可见 | 仅公示陈述可见 | — | — |
| 机构（白名单） | **永不可见** | 仅 API 白名单字段 | 仅公示陈述 | 查询+计费 | — |
| 平台运营 | **无权读取**（架构性规避） | 审核后台（定向审核） | 审核后台 | 计费审计 | 结算 |
**关键设计原则**：平台对 Vault 区的"不可见"不是权限配置，而是架构性事实——Vault 明文只存在于用户设备 SM4 加密沙箱，服务器只有加盐哈希。

## 5. 功能需求详述
### 5.1 模块 A：公示管理（Plaza 核心）
**FR-A1 公示开关**
| 项 | 规格 |
|---|---|
| 默认状态 | **全部字段默认不公示**，用户须显式 opt-in |
| 可选字段 | ① 存证关系数（区间显示，如"3-5 段"，防精确数字歧视）② 关闭方式分布 ③ 完整性宣誓状态 ④ 关系陈述精选 ⑤ 注册时长 ⑥ 存证徽章 |
| 禁止字段 | 具体日期、前任任何信息、未公示关系的存在本身、精确数字 |
| 撤回 | 一键撤下，公开页 ≤ 1 分钟下线，API ≤ 5 分钟失效（撤回即生效，依《个保法》第15条"便捷的撤回同意方式"） |
| 修改频率 | 字段调整每日限 1 次（防反复横跳操纵） |
| 二次确认 | 公示前强制展示"此内容将对所有持有链接的陌生人可见"弹窗 |
**FR-A2 公开主页**
- 仅含公示字段摘要、存证徽章（可点击核验）、分红说明、举报入口；
- **无任何搜索入口**——只能通过用户主动分享的链接/二维码到达；
- 防爬：频次限制、无列表页、robots 屏蔽；
- 视觉规范：克制、无打分元素、无任何价值排序。
**FR-A3 完整性宣誓状态公示**
- 用户可公示"完整性宣誓状态"（✅ 已宣誓 / 未宣誓）而非宣誓内容本身；
- 一旦宣誓被证伪（法定渠道确认虚假宣誓），状态强制变更为"⚠️ 曾有虚假宣誓记录"，此变更公开且不可关闭（本产品唯一的强制公开变更）。
### 5.2 模块 B：关系陈述（二人实名评价）
**定位**：附加功能，非核心。目的是为公示档案增加"来自前关系方的证言"，提升可信度立体感。
**FR-B1 提交资格**
| 项 | 规格 |
|---|---|
| 资格 | 双方**均已实名核身** + 该关系**已双签关闭**（和平关闭或单方注销满 30 天） |
| 唯一性 | 每段关系每人仅 1 份陈述，提交后 7 天内可修改，之后锁定 |
| 长度 | ≤ 200 字 |
**FR-B2 内容合规（三层过滤）**
| 层 | 机制 |
|---|---|
| L1 自动 | PII 正则拦截（姓名/手机号/身份证/微信号 100% 拦截） |
| L2 敏感词 | 敏感词库初筛 + 抽样人工复审 ≥ 20% |
| L3 举报 | 举报通道 + 通知删除响应 ≤ 24h（《民法典》1195-1197 条义务） |
**FR-B3 双向并列展示（法律核心）**
- A 的陈述与 B 的答辩**永远并列展示**，不可单方删除对方文本；
- 未提交方显示"对方已提交陈述，你未提交"（中性文案，无催促暗示）；
- 双方均未提交显示"双方均未提交陈述"（完全中性，不暗示"有问题"）。
**FR-B4 法律告知（提交前强制）**
> "陈述一旦提交将与其公开档案关联，构成个人信息处理；涉诽谤责任由发布者承担。你的实名信息与关系存证已绑定，追责链条完整。"
**FR-B5 存储**
- 明文存 Plaza 区服务器，**与 Vault 区物理隔离的独立数据库**；
- 公示撤下时，陈述同步从公开页消失，服务器保留 ≤ 30 天后删除。
**与看准网模式的根本差异**（用于对外传播与监管沟通）：实名核身+存证关系绑定使**责任链条天然完整**——评价者身份、关系存在性、评价内容三者哈希关联，取证成本极低。这是本产品与匿名评价平台的本质区别。
### 5.3 模块 C：机构 API（营收核心）
**FR-C1 场景 A：批量查询公示信息**
| 项 | 规格 |
|---|---|
| 数据范围 | **仅 Plaza 已公示字段**，不含 Vault 任何数据 |
| 法律依据 | 《个保法》第 27 条：个人自行公开的信息可在合理范围内处理，**个人明确拒绝的除外** |
| 撤回效力 | 用户撤下公示后，API 即时失效；机构须实时校验或约定次日失效（合同+技术双保险） |
| 计费 | 按次计费，套餐预充值；单机构 QPS ≤ 1 |
| 分红 | 被查用户获查询费 30% 分成（详见 FR-E1） |
**FR-C2 场景 B：本人现场授权传输**
法律依据：《个保法》第 23 条"向第三方提供"须告知接收方名称、联系方式、处理目的、处理方式、信息种类并**取得单独同意**。
**OAuth 2.0 授权码流程**（业界标准，杜绝密码式授权）：
```
① 用户在机构门店/机构 App 内点击"授权盟书档案"
② 跳转盟书授权页（显示六要素：机构名/联系方式/目的/字段/保存期限/权利告知）
③ 用户逐项勾选授权字段 → 确认
④ 盟书生成授权码返回机构
⑤ 机构凭授权码换取访问令牌（access_token，短时效）
⑥ 机构凭令牌拉取授权字段
⑦ 传输凭证写入用户"授权记录"（可查、可撤销协助转发）
```
| 项 | 规格 |
|---|---|
| 令牌时效 | access_token 有效期 ≤ 10 分钟，仅限单次拉取 |
| 传输内容 | **传摘要不传明细**：存证数、宣誓状态、公示陈述——Vault 明细永不出境 |
| 审计 | 全部授权/查询/修改日志保留 ≥ 3 年，用户可查 |
| 删除协助 | 用户日后行使删除权时，平台协助通知机构 |
| 费用 | 场景 B 传输本身**免费**（降低机构接入门槛），机构仅付系统对接开通费 |
**FR-C3 机构准入**
- 企业资质审核 + 行业备案 + 数据合规承诺书 + 白名单制；
- 合同必备条款：用途限定（仅婚恋服务核验）、禁止缓存转售、违约金、审计权、黑名单机制、吊销 API 资质条款。
### 5.4 模块 D：非定向广告位
| 项 | 规格 |
|---|---|
| 位置 | 仅公开页底部 + "发现"页信息流；**App 主功能界面零广告** |
| 形式 | 非定向品牌广告（无用户画像可用于定向，对广告主如实告知） |
| 行业白名单 | 婚恋类允许（与 B 端客户重合）；金融/医疗/游戏一律拒接 |
| 依据 | 《广告法》合规审查 |
### 5.5 模块 E：数据分红钱包
| 项 | 规格 |
|---|---|
| 入账 | 场景 A 每次查询，被查用户获 30% 分成，T+1 入账 |
| 提现门槛 | 满 50 元可提现（实名收款，此处为平台处理用户金融信息的少有场景，**单独告知同意**）或全额抵扣增值服务 |
| 明细 | 与对应查询记录一一可查 |
### 5.6 模块 F：隐私中心
- 全部授权记录导出（何时向哪家机构传了什么）；
- 全部被查记录查询（谁/何时/查了什么）；
- 一键删除 Plaza 全部数据；
- Vault 本地密钥销毁入口（本地明文+salt 物理不可恢复，链上哈希因失去攻击面而依《个保法》第 4 条匿名化条款视为完成删除义务）。

## 6. 用户故事与验收标准
### 6.1 主路径
| ID | 用户故事 | 验收标准 |
|---|---|---|
| US-01 | 作为认真恋爱者，我想与对方进行双签互证，以便这段关系被郑重记录且不可抵赖 | 双签成功后链上可查，任一方事后篡改本地记录，重算哈希与链上不匹配，篡改立即暴露 |
| US-02 | 作为经历清白者，我想把档案摘要挂到 Plaza 公示，以便让"可信"成为择偶竞争力 | 公示后生成公开链接，陌生人打开可见所选字段，字段区间化显示 |
| US-03 | 作为求证者，我想验证对方出示的公示档案真实性，以便了解其真实经历 | 公开页存证徽章可点击核验，链上哈希比对通过显示 ✅ |
| US-04 | 作为公示用户，我想随时一键撤下公示，以便收回对公开信息的控制 | 撤下后公开页 ≤ 1 分钟下线，API ≤ 5 分钟失效，机构系统显示"数据已失效" |
| US-05 | 作为机构，我想批量查询用户公示信息，以便为客户提供核验服务 | 仅返回 Plaza 白名单字段，无 Vault 数据路径可达；撤回用户数据实时失效 |
| US-06 | 作为到店客户，我想现场授权机构获取我的档案摘要，以便替代手工誊抄 | OAuth2.0 授权码流程，六要素弹窗，传摘要不传明细 |
| US-07 | 作为被查用户，我想知道谁查了我并因此获得收益，以便对数据流通保持控制 | 每次查询实时通知，分红 T+1 入账，明细一一对应 |
### 6.2 失败路径与边界
| ID | 用户故事 | 验收标准 |
|---|---|---|
| US-F1 | 作为求证者，我输入的授权码已过期，想知道发生了什么 | 显示"授权码已过期"，不显示是否曾被使用 |
| US-F2 | 作为用户，我拒绝机构的现场授权请求 | 机构收不到拒绝原因，仅显示"用户未授权" |
| US-F3 | 作为公示用户，我撤回公示后机构要求我解释为什么撤回 | 平台不提供撤回原因给机构（合同禁止+技术不存） |
| US-F4 | 作为用户，我在关系存续期想单方注销 | 链上标记"单方注销"，对方收到通知可附说明，双向可见 |
| US-F5 | 作为未成年人（未满 18 周岁），我尝试注册 | 实名核身年龄校验拒绝，无任何档案建立 |
| US-F6 | 作为用户，我换手机了 | 助记词+硬件密钥迁移，不提供服务器备份（服务器无数据可备份） |
| US-F7 | 作为陈述提交方，我提交了含手机号的陈述 | PII 正则 100% 拦截，提示"含敏感信息请修改" |
| US-F8 | 作为被陈述方，我认为对方陈述诽谤 | 举报通道 → 人工审 → 通知删除 ≤ 24h，我方可提交答辩并列展示 |

## 7. 边界与异常场景
| 场景 | 处理规则 |
|---|---|
| 授权弹窗用户长时间未响应 | 场景 B 等待上限 10 分钟，超时视为拒绝，机构显示"用户未响应" |
| 机构缓存数据用于超范围用途 | 合同违约金 + 审计权 + 黑名单 + 吊销 API 资质 |
| 陈述涉名誉权纠纷 | 通知-删除通道 + 实名追责威慑（责任链条完整） |
| 公示成为机构隐性门槛（软强制） | 监测公示率与撤回率，若机构普遍要求公示则推动行业公约"未公示不得歧视" |
| 宣誓被证伪 | 宣誓状态强制变更为"曾有虚假宣誓记录"，公开且不可关闭 |
| 未成年人 | 注册即拒，核身年龄校验 |
| 用户死亡 | Vault 数据随设备消失；Plaza 数据依近亲属申请删除（依《个保法》第 49 条） |

## 8. 非功能需求
### 8.1 安全
- 传输：TLS 1.3 + 国密 SM2/SM4 双证书；
- Vault：iOS Keychain/Secure Enclave、Android Keystore/StrongBox，SM4 本地加密，密钥永不出安全芯片；
- Plaza 库：AES-256，密钥 HSM 管理；
- 哈希加盐：所有上链哈希 HMAC-SM3，防字典攻击；
- 渗透测试：年检，Vault/Plaza 隔离性为必测项（任何 API 路径不可达 Vault 数据）。
### 8.2 合规（法务审核清单，上线前逐项通过）
| # | 项目 | 法条依据 | 状态 |
|---|---|---|---|
| 1 | Plaza 公示 opt-in 默认关闭 + 单独同意 | 个保法 25 条 | 待法务复核 |
| 2 | 关系陈述"通知-删除"通道 ≤ 24h | 民法典 1195-1197 条 | 待法务复核 |
| 3 | 场景 A 撤回即失效机制 | 个保法 27 条但书 | 待法务复核 |
| 4 | 场景 B 六要素告知 + 单独同意 | 个保法 23 条 | 待法务复核 |
| 5 | Vault 敏感信息上链前单独同意 | 个保法 28-30 条 | 待法务复核 |
| 6 | 授权记录导出与删除协助 | 个保法 44-47 条 | 待法务复核 |
| 7 | ICP/EDI/区块链信息服务备案 | 行业资质 | 流程中 |
| 8 | 广告法行业白名单 | 广告法 | 待法务复核 |
| 9 | 未成年人保护 | 未成年人保护法 | 待法务复核 |
| 10 | 机构合同禁止缓存/转售/超范围条款 | 个保法 20 条 | 待法务复核 |
### 8.3 性能
- 公开页 P95 < 500ms；
- 场景 B 授权等待上限 10 分钟；
- 锚定批量 Merkle 每小时（捐赠不足降级为每日）；
- API 单机构 QPS ≤ 1。

## 9. 埋点方案与指标体系
| 层级 | 指标 | 埋点字段口径 |
|---|---|---|
| 北极星 | 月互证次数 | 双签成功事件计数 |
| 北极星 | 月 API 有效查询量 | 场景 A + 场景 B 返回成功事件计数 |
| 裂变 | K 系数 | 新用户来源标记 = "互证邀请"的比例 |
| 公示健康度 | 公示率 / 7 日公示留存 | 公示用户 / 活跃用户；7 日内未撤下比例 |
| 公示健康度 | 撤回率 | 24h 内撤回 / 公示操作 |
| 商业 | 机构 ARPU | 机构月付费 / 机构数 |
| 商业 | 查询→授权转化率 | 场景 B 弹窗确认 / 弹窗展示 |
| 信任红线 | 授权弹窗拒绝率 | 拒绝 / 弹窗展示（拒绝率骤升=公信力预警） |
| 陈述质量 | 举报率 / 删除率 | 举报 / 陈述数；24h 删除 / 举报 |
**数据看板**：运营后台每日刷新，公示率与授权拒绝率为红线预警指标。

## 11. 法务审核清单（单独冻结项）
1. 公示管理弹窗的"单独同意"法律文案；
2. 关系陈述提交前的法律告知文案（诽谤责任+追责链条）；
3. 场景 B 六要素授权弹窗的完整性与可读性；
4. 机构合同模板（禁止缓存/转售/超范围/违约金/审计权）；
5. 隐私政策修订（新增 Plaza 公示、机构 API、数据分红条款）；
6. 宣誓证伪变更的强制公开机制的法律定性；
7. 用户死亡数据处置流程。

## 13. 附录
### 13.1 术语表
| 术语 | 含义 |
|---|---|
| Vault 区 | 用户自持的关系档案区，明文仅存设备，服务器零存储 |
| Plaza 区 | 用户自愿公示的公开区，存服务器，可随时撤下 |
| 双签 | 双方各自用 SM2 私钥对同一哈希签名 |
| 完整性宣誓 | 用户对"本档案即全部"的数字签名，可被日后证伪 |
| 场景 A | 机构批量查询 Plaza 公开信息（付费 API） |
| 场景 B | 本人现场授权 → OAuth2.0 → API 传输至机构系统（免费） |
| 数据分红 | 被查用户获查询费 30% 分成 |
| 墓碑交易 | 删除后上链的 {digest, deleted_at} 记录 |
### 13.2 机构 API 规格摘要
```
场景 A：POST /v1/public/query
  认证：mTLS + IP 白名单 + API Key
  请求：{ subject_public_id, fields[] }
  响应：{ granted_fields, attestation_hash, verify_url, valid_until }
场景 B：POST /v1/consent/init  → 返回授权 URL
      GET  /v1/consent/callback → 用户确认后回调
      POST /v1/consent/exchange → 授权码换 access_token（时效≤10min）
      GET  /v1/consent/data     → 凭令牌拉取授权字段（一次性）
```
