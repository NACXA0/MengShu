# 《盟书 PactBook》UI 设计规范 / 视觉规范
**版本**：v1.0 | **状态**：设计评审稿 | **密级**：内部
**关联文档**：PRD v1.0、SRS v1.0
**适用范围**：iOS / Android / 微信小程序三端，含公开网页（公开主页/核验页）
---
## 0. 设计价值观：一句话讲清楚
**盟书的界面不是游乐园，是公证处。**
用户在这里签署的是人生中最严肃的承诺之一，界面的首要职责是传达"值得托付"，而非"好玩好看"。因此本规范的核心判据只有一条：
> **每一个视觉决策都必须回答：这个设计让用户更信任这个产品了吗？**
由此推导出五条设计价值观，凌驾于所有具体规则之上：
| # | 价值观 | 反面案例 |
|---|---|---|
| D1 | **克制**——界面为内容服务，不与内容竞争注意力 | 彩虹渐变、大面积插画、弹跳动效 |
| D2 | **庄重**——关系存证是严肃行为，视觉语言须匹配 | 粉色系、卡通 IP、俏皮文案 |
| D3 | **诚实**——界面上出现的每个元素都有真实功能，无装饰性欺骗 | 假进度条、无意义的"安全等级"图标堆砌 |
| D4 | **可预期**——用户永远知道下一步会发生什么 | 隐藏式操作、 surprise 弹窗 |
| D5 | **无评判**——系统对关系内容保持绝对中立，视觉上不暗示任何价值判断 | 评分星星、排行榜、"优质关系"标签 |
**D5 是本产品的红线级设计原则**：整个产品不允许出现任何形式的评分、排序、比较视觉元素。这不是风格偏好，是产品定位（PRD §2.3 范围外）。

## 1. 双区视觉区分系统
双区架构（Vault/Plaza）是产品的灵魂，必须让用户在任何界面一眼分辨自己处于哪个区——这既是信息架构需求，也是安全需求（防止用户误以为私密内容已被公示）。
| 维度 | Vault 保险库 | Plaza 广场 |
|---|---|---|
| **背景基色** | 墨蓝黑 `#0D1B2A` | 暖白 `#FAFBFC` |
| **标题字体** | 思源宋体 SemiBold（衬线，庄重） | 思源黑体 Medium（无衬线，轻盈） |
| **主色应用** | 哑光金 `#C9A961`（点缀，仪式感） | 藏青 `#1B3A5C`（主色，信任感） |
| **排版密度** | 紧凑（信息层级高） | 宽松（阅读友好） |
| **图标隐喻** | 锁、盾、印章 | 门、窗、招牌 |
| **顶部区标识** | 常驻"🔒 Vault"胶囊标识 | 常驻" Plaza"胶囊标识 |
| **进入动效** | 上滑+变暗（进入保险库） | 下滑+变亮（走出到广场） |
**强制规则**：两区之间任何跳转必须经过明确过渡动画（≥400ms），不允许生硬切换——用户须清楚感知"我换区了"。

## 2. 色彩系统
### 2.1 主色
依据信任类产品色彩惯例，选择藏青（Navy Blue）作为主色——传达机构级可靠性，同时刻意区别于婚恋产品的粉色/红色与社交产品的多彩。
| Token | 色值 | 用途 |
|---|---|---|
| `color.primary.900` | `#12293E` | 主色最深（标题、强调） |
| `color.primary.700` | `#1B3A5C` | 主色标准（按钮、链接） |
| `color.primary.500` | `#2C5282` | 主色次级（hover态） |
| `color.primary.100` | `#EBF1F7` | 主色极浅（背景、选中态） |
### 2.2 Vault 专属色
| Token | 色值 | 用途 |
|---|---|---|
| `color.vault.bg` | `#0D1B2A` | Vault 区背景 |
| `color.vault.surface` | `#152238` | Vault 卡片背景 |
| `color.vault.accent` | `#C9A961` | 哑光金（仪式感点缀） |
| `color.vault.text` | `#E8ECEF` | Vault 主文本 |
### 2.3 功能色
| Token | 色值 | 语义 |
|---|---|---|
| `color.success` | `#2F855A` | 签署成功、存证完成 |
| `color.warning` | `#B7791F` | 待确认、即将过期 |
| `color.error` | `#C53030` | 失败、证伪、删除 |
| `color.info` | `#2B6CB0` | 提示、说明 |
### 2.4 中性色阶
| Token | 色值 | 用途 |
|---|---|---|
| `color.neutral.900` | `#1A202C` | 主文本 |
| `color.neutral.600` | `#4A5568` | 次文本 |
| `color.neutral.400` | `#A0AEC0` | 辅助文本、占位符 |
| `color.neutral.200` | `#E2E8F0` | 分割线 |
| `color.neutral.50` | `#F7FAFC` | 页面背景 |
### 2.5 色彩使用约束
**禁止使用**：粉色系（婚恋暧昧暗示）、亮红（攻击性）、彩虹渐变（娱乐化）、荧光色（轻浮）。**克制的配色本身就是信任信号**——研究显示，用户将视觉上的节制与可靠性相关联。
**对比度强制标准**：全部文本对比度 ≥ WCAG 2.1 AA（4.5:1 正文 / 3:1 大文本）。哑光金在深色背景上作为文本时须用 `#D4B876` 提亮一档。
### 2.6 深色模式
全产品支持深色模式，映射规则：
- Plaza 区深色模式 = 藏青深灰 `#1A202C`（非纯黑，保留温暖感）
- Vault 区无"深色模式"概念（本身即深色）
- 哑光金在浅色模式下加深至 `#9C7A3C`

## 3. 字体系统
### 3.1 字族
| 用途 | 中文 | 英文/数字 |
|---|---|---|
| 标题 | 思源宋体 | Playfair Display |
| 正文 | 思源黑体 | Inter |
| 代码/哈希/存证编号 | — | JetBrains Mono |
**宋体用于标题的设计意图**：衬线字体在中文语境中传达"契约感、文书感、庄重感"——如同法律文件与公证书的排版惯例，与产品的司法属性形成视觉呼应。正文用黑体保证长文本可读性。
**等宽字体强制场景**：所有哈希值、存证编号、tx_id、时间戳一律 JetBrains Mono——等宽字体的"技术精确感"强化密码学信任。
### 3.2 字阶
| Token | 字号/行高/字重 | 用途 |
|---|---|---|
| `type.display` | 34/44 / 宋体 SemiBold | 双签完成仪式页大标题 |
| `type.h1` | 28/38 / 宋体 SemiBold | 页面主标题 |
| `type.h2` | 22/30 / 黑体 Medium | 区块标题 |
| `type.h3` | 18/26 / 黑体 Medium | 卡片标题 |
| `type.body` | 16/26 / 黑体 Regular | 正文 |
| `type.body-sm` | 14/22 / 黑体 Regular | 次级正文 |
| `type.caption` | 12/18 / 黑体 Regular | 说明、时间戳 |
| `type.mono` | 14/22 / JetBrains Mono | 哈希、编号 |
**字号红线**：正文不得小于 14pt（可读性底线），说明文字不得小于 12pt。法律告知文本（授权弹窗、陈述提交门）**禁止小于 14pt**——合规文本的可读性是法律义务而非排版偏好。

## 4. 间距与栅格系统
### 4.1 间距基准
**4px 基准网格**，全部间距取值为 4 的倍数：
| Token | 值 | 典型用途 |
|---|---|---|
| `space.xs` | 4px | 图标与文字间距 |
| `space.sm` | 8px | 相关元素内间距 |
| `space.md` | 16px | 卡片内边距、列表项间距 |
| `space.lg` | 24px | 区块间距 |
| `space.xl` | 32px | 页面左右边距 |
| `space.2xl` | 48px | 大区块分隔 |
| `space.3xl` | 64px | 仪式页留白 |
### 4.2 栅格
- 移动端：单列流式布局，左右边距 `space.xl`（32px）
- 公开网页：12 栅格，最大宽度 1200px，内容区 720px（阅读友好）
- 卡片内边距统一 `space.md`（16px）
### 4.3 圆角
| Token | 值 | 用途 |
|---|---|---|
| `radius.sm` | 2px | 小型元素（标签、徽章） |
| `radius.md` | 4px | 按钮、输入框 |
| `radius.lg` | 8px | 卡片 |
| `radius.full` | 999px | 胶囊标识、头像 |
**设计意图**：刻意使用小圆角（2-8px）而非流行的大圆角（16px+）——小圆角传达"严谨、精确"，大圆角传达"轻松、友好"，后者与产品定位冲突。

## 5. 组件规范
### 5.1 核心组件清单
| 组件 | 变体 | 状态 | 设计要点 |
|---|---|---|---|
| **Button** | Primary / Secondary / Ghost / Danger | Default / Pressed / Disabled / Loading | 主按钮藏青填充白字；加载态显示锚定进度；危险按钮仅用于删除/撤销 |
| **Card** | Vault卡 / Plaza卡 / 陈述卡 | — | Vault 卡深色表面+金色边框1px；Plaza 卡白底+浅阴影 |
| **Input** | 文本 / 多行 / 授权码 | Default / Focus / Error / Disabled | 等宽字体输入框用于哈希/编号；错误态红色描边+下方提示 |
| **Switch** | 公示开关 | On / Off / Disabled | **公示开关必须比普通开关更大（44pt 高）**——法律意义上的"同意"动作值得更大的视觉分量 |
| **Badge** | 存证徽章 / 区标识 / 状态徽章 | — | 存证徽章：盾牌+链环图形，哑光金描边 |
| **Modal** | 确认 / 法律告知 / 授权弹窗 | — | 见 §5.2/5.3 专项规范 |
| **Toast** | 成功 / 失败 / 信息 | — | 顶部下滑出现，2.5s 自动消失；**拒绝类 Toast 不出现任何原因** |
| **List Item** | 关系项 / 授权记录 / 查询记录 | — | 双列布局：左侧主信息，右侧时间戳（等宽字体） |
### 5.2 授权弹窗（场景 B 六要素）——本产品最重要的组件
依《个保法》第 23 条与 PRD FR-C2，授权弹窗为**全屏独立页**，不得使用底部弹层或居中小弹窗（弱化感知）。结构自上而下：
```
┌──────────────────────────────────────┐
│  [机构 Logo]                          │
│  机构名称（h1，18pt+）                 │
│  联系方式（mono 14pt）                 │
├──────────────────────────────────────┤
│  处理目的说明（body 14pt+）            │
├──────────────────────────────────────┤
│  ▢ 字段一（如：存证关系数区间）        │
│  ▢ 字段二（如：完整性宣誓状态）         │
│  ▢ 字段三（如：公示陈述精选）          │
│  （逐项勾选，默认全部不勾）            │
├──────────────────────────────────────┤
│  保存期限：[期限说明]                  │
│  你的权利：[删除/撤回说明]             │
├──────────────────────────────────────┤
│  [拒绝（次要按钮）]  [允许本次（主按钮）]│
│  [允许该机构90天（次次要，小字）]       │
└──────────────────────────────────────┘
```
**强制规则**：
1. 拒绝按钮与允许按钮**等视觉权重**——不得通过颜色/大小弱化拒绝选项（暗黑模式红线）；
2. 六要素（机构名/联系方式/目的/字段/期限/权利告知）缺一不可，缺失任一项弹窗禁止渲染；
3. 字段勾选不得提供"全选"快捷方式——逐项确认才能构成有效单独同意；
4. 弹窗背景遮罩透明度 ≥ 70%，强制阻断下层界面。
### 5.3 法律告知门（陈述提交前）
模态全屏，阅读完成后"我已阅读并理解"按钮才可点击（滚动到底自动激活，非倒计时）。文案排版使用 `type.body`（14pt+），关键责任条款加粗。
### 5.4 存证徽章
统一视觉语言：**盾形轮廓 + 内部链环节点图形**。
- 已锚定：哑光金描边 + 内部实心
- 待锚定：灰色描边 + 虚线内部
- 证伪状态：红色描边 + 警示图形
点击徽章展开存证详情卡：哈希值、tx_id、Merkle proof、时间戳（全部等宽字体，附"复制"与"链上核验"跳转）。
### 5.5 关系陈述卡（双向并列）
依 PRD FR-B3，陈述与答辩**永远并列展示于同一卡片内**，视觉等权重：
```
┌────────────────────────────────┐
│  A 方陈述（发布于 2026-10-01）   │
│  [陈述内容，body 16pt]           │
├────────────────────────────────┤
│  B 方答辩（发布于 2026-10-03）   │
│  [答辩内容，body 16pt]          │
└────────────────────────────────┘
```
两侧使用同字号、同颜色、同间距——**不存在任何视觉上的"主次""优劣"暗示**。未提交方显示中性占位："对方已提交陈述，你未提交"（灰字，无箭头、无催促图形）。
### 5.6 公示开关组件
公示开关（FR-A1）是法律意义上的"同意"操作，设计规格高于普通开关：
- 尺寸：高 44pt（远大于标准开关）
- 开启时需二次确认弹窗："此内容将对所有持有链接的陌生人可见"
- 关闭（撤下）时触发门关闭动效（见 §7.4），并显示"API 将在 5 分钟内失效"提示

## 6. 图标与插画风格
### 6.1 图标
- **风格**：线性图标，1.5pt 描边，直角端点——精确、克制
- **图标库**：Lucide / Phosphor（线性变体），禁止填充式卡通图标
- **隐喻系统**：
| 概念 | 图标隐喻 | 禁用隐喻 |
|---|---|---|
| Vault | 锁、盾 | 心形锁（浪漫化） |
| Plaza | 门、招牌、窗 | 舞台（表演暗示） |
| 存证 | 盾+链环 | 对勾（过于简单化） |
| 关系 | 两个交叠的圆环 | 心形、爱心 |
| 删除 | 碎纸机、墓碑 | 垃圾桶（轻浮） |
### 6.2 插画
**原则上不使用插画**。产品严肃性决定视觉表达以文字与图标为主，插画弱化庄重感。
唯一例外：空状态（Empty State）允许使用**极简线条插画**（单色藏青线稿，不超过 3 个元素），如空关系列表的"两个分离的圆环"示意。

## 7. 动效规范
动效的唯一目的：**强化仪式感与状态反馈**，绝不为娱乐。
### 7.1 时长标准
| 类型 | 时长 | 缓动 |
|---|---|---|
| 微反馈（按钮按压） | 100ms | ease-out |
| 状态切换（卡片展开） | 250ms | ease-in-out |
| 区切换（Vault↔Plaza） | 400ms | custom（见下） |
| 仪式动效（双签完成） | 1200-1800ms | 专属设计 |
### 7.2 双签完成动效（产品核心仪式）
设计语言：**印章落下 + 哈希粒子聚合**。
```
时间轴（总时长 1500ms）：
  0-300ms   双方签名图形从两侧向中心汇合
  300-600ms 汇合点爆发金色粒子（SM3 哈希可视化隐喻）
  600-1000ms 粒子聚合成印章轮廓
  1000-1500ms 印章"落下"（scale 1.2→1.0 + 轻微震动反馈）
             下方浮现 "存证编号: 0x..."（等宽字体，打字机效果）
```
伴随触觉反馈（iOS Core Haptics / Android VibrationEffect，单次中等强度）。**震动是仪式感的一部分——签字需要"手感"**。
### 7.3 上链成功反馈
后台异步操作，成功时状态栏（顶部常驻）从"待锚定 → 已锚定"切换，存证徽章由灰变金。**不使用全屏弹窗打断用户**——上链是预期内的后台行为。
### 7.4 撤销公示动效
公开页下线时：页面内容收拢至门形图形 → 门关闭（两扇合拢）→ 淡出。传达"你的招牌已摘下"的具象感受。
### 7.5 禁用动效
- 弹跳、抖动（除非错误反馈）
- 连续循环动画（诱导注意力）
- 3D 翻转（炫技无意义）
- 任何出现在 Vault 区的"欢快"动效

## 8. 三端适配规范
### 8.1 iOS（Human Interface Guidelines）
- **导航**：底部 Tab Bar（4 个：Vault / Plaza / 发现 / 我的）
- **字体**：正文优先 SF Pro（英文环境），中文回退思源黑体
- **触控目标**：≥ 44×44pt
- **手势**：左滑返回；Vault 区禁用下拉刷新（防误触）
- **安全区**：全面屏设备遵守 Safe Area（顶部 44pt / 底部 34pt）
### 8.2 Android（Material Design 3）
- **导航**：底部 Navigation Bar（与 iOS 保持一致，M3 已支持）
- **字体**：Roboto（英文）+ 思源黑体（中文）
- **触控目标**：≥ 48×48dp
- **返回**：系统返回手势支持，Vault 区返回须二次确认（防误退出加密区）
- **FAB**：不使用（产品无高频"创建"场景，双签入口放在卡片内）
### 8.3 微信小程序（轻功能版）
依 SRS §2.1，小程序**仅含公开页查看 + 授权码验证**，不含 Vault 双签（密钥安全不达标）。
- 视觉与主 App 保持一致（同一 Design Token 源）
- 公开页适配小程序导航栏（自定义导航栏保持品牌一致性）
- 授权码验证页支持扫码直达
### 8.4 公开网页（公开主页 / 核验页）
- 响应式：移动端单列（720px 内容区），桌面端 12 栅格（1200px）
- 性能预算：P95 < 500ms（NFR-P1），首屏无外部字体阻塞（宋体降级为系统衬线）

## 9. 关键页面设计约束
依 PRD §2.7，对产品最关键的新界面给出专项约束：
### 9.1 公开主页（FR-A2）
- **视觉克制基线**：白底、藏青主文字、无渐变、无大面积色块
- **禁止元素**：任何评分、排序、对比图形；"优秀""清白"等价值判断词汇；社交分享浮动按钮（仅页底固定分享条）
- **必含元素**：摘要卡片、存证徽章（可点击核验）、分红说明（固定页底）、举报入口（右上角，不隐藏）
- **页面氛围**：像一份公证书的电子版，而非社交媒体主页
### 9.2 双签仪式页
- 全屏沉浸式，无导航栏干扰（顶部仅有"×"退出）
- 背景使用 Vault 深色 + 微弱纹理（如羊皮纸暗纹，透明度 3%）
- 完成后停留 3 秒展示存证编号，再提供"分享给对方"按钮
### 9.3 隐私中心
- 信息密度优先于美观——这是用户行使法定权利的工具页
- 授权记录、被查记录使用表格布局（时间/对象/内容三列）
- "一键删除 Plaza 全部数据"按钮使用 Danger 变体 + 二次确认
### 9.4 拒绝无痕的视觉处理（FR-B3 / US-F2）
拒绝/超时后邀请方界面**视觉恒定为"等待对方响应"**——无已读图标、无超时倒计时、无任何状态变化的微动效。**这不是信息设计问题，是隐私设计问题**：拒绝本身是敏感信息。
---
## 10. 广告位视觉规范（FB-03）
依 PRD FR-D，广告位仅出现在公开页底部与发现页信息流，须遵守：
- **视觉隔离**：广告卡片与内容卡片之间以 `space.2xl`（48px）分隔 + "广告"标签（灰底白字，10pt，固定左上角）
- **禁止**：全屏广告、插屏广告、开屏广告、信息流伪装（广告卡片不得模拟内容卡片样式）
- **主功能区零广告**：Vault 区、双签流程、授权弹窗、隐私中心**永不出现广告**——这些场景的广告会摧毁信任主张

## 结语：克制即设计
本规范的全部规则可以收敛为一句话：**当拿不准某个设计是否合适时，问自己"公证处会这样设计吗"——答案通常是否定的。**
盟书卖的是"可信"。而信任的视觉语言，从来不是热闹、鲜艳、讨喜——是沉稳、精确、克制。用户把人生最严肃的承诺交到这里，界面欠他们一份与之匹配的庄重。
多余的每一笔装饰，都是在稀释"可信"二字。
